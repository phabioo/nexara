# Decisions

Settled decisions. Change them only deliberately and record the change here.

| # | Decision | Reason |
| --- | --- | --- |
| 1 | Hub + Grid Agent architecture; agents connect outbound to the hub | Cross-platform later, no open ports on hosts, no root SSH keys stored on the hub |
| 2 | Hybrid enrollment: SSH once to install the agent, then agent only; manual token enrollment as alternative | Convenient for Linux, works for Windows/macOS later |
| 3 | Hub runs on the Pi 5 `frpi5` | Most capable device in the network |
| 4 | The hub manages itself via its own Grid Agent | Appears like every other host |
| 5 | Shell runs as the Pi's normal sudo user, never root | Least privilege, same as SSH login |
| 6 | Friends run their own instance; no multi-tenant hub | Keeps auth and data model simple and safe |
| 7 | Remote access only through the existing WireGuard VPN | No public exposure of a root-capable dashboard |
| 8 | Stack: Go stdlib + html/template + HTMX (+SSE) + plain CSS; xterm.js for the shell only | Lightweight, no frontend build |
| 9 | YAML for startup config only; SQLite (`modernc.org/sqlite`, no CGO) for state | Hand-editable config, safe concurrent state |
| 10 | Hub ↔ agent: WebSocket + JSON over mTLS, hub is its own CA | Simple, bidirectional, revocable |
| 11 | argon2id passwords, TOTP 2FA (optional v0.1, mandatory v0.2), CSRF, strict CSP, audit log | Security baseline |
| 12 | First run: setup mode with one-time setup code in the journal (60 min, auto-renew, `sudo nexus setup code`, 5 tries → 15 min lock) | Nobody else in the LAN can claim a fresh hub |
| 13 | Alerts: dashboard only at first, e-mail later; no cloud push | Local-only principle |
| 14 | Extra features: Power (WoL/reboot/shutdown), history, alerts, Docker | Chosen scope beyond monitoring, packages, shell |
| 15 | Brand: Nexara (company), Nexus (hub/dashboard), Grid (host management/agent), Shell (terminal); mark = split hex, wordmark = Instrument Serif | Consistent naming in UI, code and docs |
| 16 | UI language English | Consistent with the design |
| 17 | One terminal command on the hub device installs everything; afterwards all administration happens in Nexus | Simplest setup for me and friends |
| 18 | Installer prints URL, setup code and certificate fingerprint; setup wizard step "Trust" installs the Nexara CA on devices | One browser warning at most, verifiable |
| 19 | Certificates include hostname, hostname.local (mDNS) and all IPs; hub re-issues them itself | Works without a DNS entry |
| 20 | Agent binaries are embedded in the hub; hub auto-updates agents | No internet needed for enrolling/updating agents |
| 21 | Self-update from Settings (opt-in GitHub check or uploaded file), signed, backup first, automatic rollback | Updates without terminal |
| 22 | Per-host job queue with live output, dpkg-lock wait, reboot-required detection | Safe, visible apt operations |
| 23 | Nightly + pre-update backups on the hub, encrypted download, restore in setup wizard (v0.2, see #28) | Recover from SD-card failure |
| 24 | Public monorepo github.com/phabioo/nexara (Go module `github.com/phabioo/nexara`); GitHub Actions builds signed releases; installer downloads from its GitHub Releases | One protocol, one version, token-free install |
| 25 | `nexus dev --demo` with simulated agents and the design's sample data | UI work without real Pis |
| 26 | Installable web app (manifest, app icon, favicon) | Feels like an app on phones and desktops |
| 27 | Audit log is written from v0.1; the audit view comes with Settings in v0.2 | No gap in the record, UI can wait |
| 28 | Backup & restore (nightly, pre-update, download, restore in setup) moves to v0.2; the "Restore" link is hidden in v0.1 (done in v0.2, see #55) | Keeps v0.1 small; belongs with Settings and self-update |
| 29 | "Keep me signed in": unchecked = browser-session cookie, checked = persistent cookie; both keep the 12 h idle timeout and a 30-day absolute limit; never skips TOTP | Survives phone/browser restarts without weakening the session rules |
| 30 | Grid Agent unit is not sandboxed (root, no `NoNewPrivileges`/`ProtectSystem`); safety comes from the fixed action list | apt, services, power and `sudo` in the shell need it |
| 31 | Views of later versions are hidden until that version ships | No dead buttons in the UI |
| 32 | YAML library `go.yaml.in/yaml/v3`; QR codes with `github.com/boombuler/barcode` (already required by `pquerna/otp`), rendered as inline SVG | Maintained YAML fork; no extra dependency for QR, CSP-friendly output |
| 33 | Jobs live in memory only (no table); `audit_log` is the record. Minute/hour history tables come with the History view in v0.2 | No new tables in v0.1; the live ring buffer covers the overview |
| 34 | `nexus dev --demo` serves plain HTTP on 127.0.0.1 only | Browsers treat localhost as secure; no certificates needed for UI work |
| 35 | `sudo nexus setup code` / `sudo nexus user reset` talk to the running service over a local admin Unix socket (`/run/nexus/admin.sock`, 0660 nexus:nexus in the 0750 `RuntimeDirectory`; root reaches it, other users do not) | No network surface, works while the service runs |
| 36 | Release signature: ed25519 over `SHA256SUMS`; verified with `crypto/ed25519` in the hub and `openssl` in `install.sh` | No extra tooling on the Pi or in Go |
| 37 | Hub code stays platform-neutral (develop on Windows); Linux-only code sits behind build tags | Fast local UI iteration |
| 38 | Enrollment runs over HTTPS `POST /grid/enroll` (token + CSR, agent pins the CA fingerprint); the response carries cert, CA, hub URL and the capabilities chosen in the UI. Self-link: the installer sets up the agent with `enroll.token_file`, the setup wizard writes that token | One enrollment path for SSH, code and self-link |
| 39 | Go directive 1.26 (required by `modernc.org/sqlite`) | Current SQLite driver |
| 40 | Enrollment-code one-liner pins the hub's server key: `curl -fsSL --insecure --pinnedpubkey sha256//<key> https://<hub>:8443/grid/install.sh \| sudo sh -s -- <code>`; the script passes the CA fingerprint to `grid-agent enroll` | New hosts do not trust the hub CA yet; pinning keeps it verifiable without a browser step |
| 41 | SSH bootstrap is two-phase: the hub first connects and shows the target's SHA256 host key fingerprint, the operator confirms it, only then does the hub authenticate (password or hub key); the confirmed fingerprint is pinned for that attempt and recorded in the audit entry. The hub's own SSH key is ed25519 in the data dir (changed after security review S-04) | The SSH password never reaches an unconfirmed host; no known_hosts management for a single install |
| 42 | Local builds, tests and preview may be blocked by Windows Smart App Control on the dev PC; GitHub Actions (Linux amd64 + arm64, `-race`) is the test authority | Keeps the dev PC's security setting untouched |
| 43 | Release signing public key lives in `deploy/keys/nexara-release.pub` (PEM, ed25519); the hub embeds it and `install.sh` carries it inline. The private key is only the GitHub Actions secret `NEXARA_RELEASE_SIGNING_KEY` (and the owner's offline backup). Signature file: `SHA256SUMS.sig`, raw 64-byte ed25519 over `SHA256SUMS` (`openssl pkeyutl -sign -rawin`) | One key, verifiable with OpenSSL 3 on the Pi and `crypto/ed25519` in Go |
| 44 | Hub package layout: the `.deb` (`nexus_<version>_<arch>.deb`) ships `/usr/bin/nexus`, `/usr/bin/grid-agent` (the hub's own agent), units in `/lib/systemd/system/`; config in `/etc/nexus/` and `/etc/grid-agent/`, data in `/var/lib/nexus/`. `install.sh` downloads and verifies the `.deb`, then installs it with `apt install`; the maintainer scripts create the `nexus` user, directories, configs and start the services. Hosts enrolled via SSH or code keep `/usr/local/bin/grid-agent` | One install path (online and offline `.deb`), distro-conform for the hub |
| 45 | The hub CA carries critical NameConstraints (permitted: `.local`, the hub's short hostnames, `localhost`, the configured agent host, loopback, RFC 1918, link-local and IPv6 ULA ranges) and is valid for 5 years; server certificates stay short-lived and are renewed automatically. The CA exists before the setup wizard asks for the agent address, so the wizard only accepts addresses the CA covers; SANs outside the constraints are dropped from server certificates. Remote access goes through the VPN (#7) (security review S-05) | A CA installed as trusted root on phones and PCs cannot be abused for other domains |
| 46 | Enrollment never replaces an existing host silently: an agent reporting an existing hostname is refused with "host exists" (UI asks for another display name); replacing a host is a separate, explicit operator action, allowed only while the old host is offline (security review S-03) | Cloned images (`raspberrypi`) and stolen codes cannot take over a host's identity |
| 47 | v0.1 can remove a host: its agent certificate is revoked (stored in the DB, checked on every TLS handshake), the live connection closes, the action is audited. Agent certificates renew over the mTLS channel (v0.2): either side triggers it 30 days before expiry, the old certificate stays of record until the agent has connected with the new one, an unused new certificate expires after 24 h (security review S-06) | A retired or stolen Pi loses access immediately |
| 48 | In-app navigation uses htmx boost with full-page answers; htmx takes `#main` plus named shell regions (tabs, nav, node card, pills, status bar) out-of-band. One unfiltered SSE stream per page: host-bound events carry the host as SSE id and the browser drops events for other hosts. No `location.reload()` except login, setup and session end; live events swap fragments. From 1024 px the views fit the viewport and long lists scroll inside their card; package lists load in pages of 60 | App-like feel without a frontend build; one connection per tab; works with a full reload of every URL |
| 49 | v0.2 storage: new SQLite tables `metrics_1m` and `metrics_1h` (history, #33) and `settings` (key-value for values changed in Settings, e.g. GitHub update check, backup options, history retention); `nexus.yaml` stays startup config only (#9) | UI-changed values are state, not startup config |
| 50 | Self-update without root in the hub: the hub downloads or receives the `.deb`, verifies `SHA256SUMS` + signature (#43) and drops a request file; a root helper (`nexus-update.path` + `nexus-update.service`) verifies the signature again on its own, takes a backup, installs with `apt`, and reinstalls the previous package if the new version does not come up healthy | The hub process never gets root; the helper trusts nothing the hub wrote |
| 51 | TOTP is mandatory from v0.2: the setup wizard has no "Skip for now"; an operator without TOTP must enroll right after the next sign-in and reaches nothing else until done. Settings shows "Require two-factor login · Required" without a toggle | v0.2 gate: no access without a second factor |
| 52 | Session idle timeout stays fixed at 12 h (CLAUDE.md); Settings shows it read-only instead of the mockup's 4/12/24 h chips | Security rule is non-negotiable |
| 53 | Update check against GitHub Releases is opt-in (default off) and the hub's only outbound connection; updating by file upload always works | Local-only principle |
| 54 | Host tabs and `Q`/`E` keep the view: on Packages a tab leads to the Packages of the other host, on Shell to its Shell, on Overview to its Overview (`hostViewURL` in `layout.go`; works without JavaScript). The target is always the plain view URL: no filter or search term is carried over (counts and states differ per host, a reload reproduces the URL). The tab of the host on screen is inert. A link clicked while another main-area request is in flight waits for it, the one in flight is dropped on arrival (no aborts, no terminal opened for hosts passed on the way); `Q`/`E` presses add up and do not move the focus into a terminal that opens meanwhile. GET answers for another host than the one on screen are discarded | Switching hosts must look like the same view with other data: no stale content, one terminal at a time, no console errors, same result for clicks and keys |
| 55 | Backups: local automatic backups are encrypted with a key derived (HKDF) from `secret.key` and serve same-device rollback; the passphrase-encrypted download is the disaster copy. `nexus backup …` drops root to the `nexus` user before touching hub files. After a restore the hub exits with a non-zero status so systemd (`Restart=on-failure`) starts it on the restored data | A compromised hub user cannot make a root process copy foreign files; no unit change needed |
| 56 | Hub-side capability switches (Settings → Hosts & capabilities) are stored in the `settings` table (`grid.caps_off.h<id>`), not in `hosts.capabilities`, which the agent's Hello overwrites on every connect. The hub refuses shell and package actions of a switched-off capability; switching the shell off closes open shells. Diagnostics shows the hub log only (in-memory ring of 1000 records, secrets redacted); agent logs would need a new agent capability and wait for a decision | A switch survives reconnects; no schema change, no new agent capability |
| 57 | `nexus dev --demo --seed` signs the demo operator in with the passphrase only (`auth.Config.DemoPasswordOnly`); `auth.NewService` refuses that switch together with Secure cookies, so the TLS hub can never use it | Demo and browser tests need no authenticator; mandatory TOTP (#51) stays intact in production |
